# 제안서 작성기

RFP 분석 완료 후 카테고리별 표준 목차로 제안서 초안을 생성한다.  
`/rfp-analyzer` 선행 실행 후 이어서 사용하는 것을 권장.

## 작성 전 필수 확인

```
[ ] RFP 분석 결과 확인 (analysis.md 또는 이전 대화)
[ ] 사업 카테고리 확인 (IT구축 / 교육 / 콘텐츠 / 기타)
[ ] 평가 기준 및 배점 확인
[ ] 회사 강점·수행 실적 정보 준비
```

---

## 표준 목차 — IT 시스템 구축

```markdown
# [사업명] 제안서

## 제1장. 사업 이해 및 환경 분석
### 1.1 사업 배경 및 목적
### 1.2 현황 분석 (AS-IS)
### 1.3 개선 방향 (TO-BE)
### 1.4 벤치마킹 사례

## 제2장. 추진 전략 및 방법론
### 2.1 추진 전략
### 2.2 개발 방법론
### 2.3 기술 아키텍처
### 2.4 핵심 차별화 요소

## 제3장. 과업 수행 계획
### 3.1 과업 범위
### 3.2 기능 설계 (요구사항별 대응)
### 3.3 시스템 구성도
### 3.4 UI/UX 설계 방향

## 제4장. 투입 인력 및 조직
### 4.1 프로젝트 조직 구성
### 4.2 핵심 인력 프로필
### 4.3 역할 및 책임 (R&R)

## 제5장. 일정 계획
### 5.1 단계별 추진 일정 (WBS)
### 5.2 마일스톤
### 5.3 산출물 목록

## 제6장. 유사 수행 실적
### 6.1 주요 수행 실적
### 6.2 프로젝트 상세 (최대 3건)

## 제7장. 기대 효과
### 7.1 정량적 기대 효과
### 7.2 정성적 기대 효과

## 제8장. 보안 및 품질 관리
### 8.1 보안 대책
### 8.2 품질 관리 계획
### 8.3 유지보수 및 기술 이전
```

## 작성 원칙

### 평가 기준 대응
- 배점이 높은 항목에 더 많은 분량과 구체성 할당
- 모든 요구사항에 명시적 대응 (요구사항 추적 매트릭스)

### 작성 톤
- 전문적이되 읽기 쉬운 한글 문체
- 수동태 지양, 능동적 표현 ("~할 것입니다" → "~합니다")
- 구체적 수치와 근거 제시 (막연한 표현 금지)
- 도표/다이어그램 자리 표시: `[그림 X-X: 설명]`

### 금지사항
- ❌ 한글 설명 없이 영어 용어만 사용
- ❌ 근거 없는 "최고", "최첨단", "혁신적" 남용
- ❌ 비현실적 일정이나 비용 제시
- ❌ 복사-붙여넣기 느낌의 범용 문구

## 출력 형식

마크다운으로 작성. 각 장은 독립 섹션으로 구분.  
각 장 끝에 `<!-- 예상 A4 분량: X페이지 -->` 주석 포함.

초안 완성 후:
1. 섹션별 리뷰 요청
2. 피그마/PPT 슬라이드 변환 여부 확인
3. 제출 서류 체크리스트 안내
