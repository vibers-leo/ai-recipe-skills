# 빈 상태·온보딩·튜토리얼 패턴

첫 사용자 경험(FTUE)은 리텐션의 80%를 결정한다. 여기서 쓰는 문구는 **정보 전달**보다 **감정 설계**에 가깝다.

## 핵심 원칙

1. **환영하되 낯간지럽지 않게.** "환영합니다!!!" 같은 강한 환영은 오히려 거리감을 만든다.
2. **다음 행동이 뭔지 명확하게.** 사용자는 어디로 가야 할지 모르면 닫는다.
3. **가치를 먼저 보여주고 요청은 나중에.** 가입/인증/결제 요구는 가능한 뒤로 미룬다.

## 빈 상태 패턴

### 첫 진입 (데이터 0개)

원본: "등록된 데이터가 없습니다."

개선:
```
아직 아무것도 없어요.
[첫 항목 만들기]로 시작해볼까요?
```

핵심: "비어 있음"을 **기회로** 포지셔닝. 다음 행동 버튼은 필수.

### 검색 결과 없음

원본: "검색 결과가 없습니다."

개선:
```
찾으시는 결과가 없어요.
다른 검색어로 찾아볼까요?
```

**팁:** 가능하다면 "혹시 이걸 찾으셨나요?" 하고 추천 검색어를 제시하면 이탈률이 크게 떨어진다.

### 필터 적용 후 결과 없음

원본: "조건에 맞는 결과가 없습니다."

개선:
```
이 조건에 맞는 결과가 없어요.
[필터 초기화]를 해볼까요?
```

**핵심:** 사용자가 스스로 "어, 이 조건이 너무 좁구나" 깨달을 수 있게 해결 경로를 제시.

## 온보딩 패턴

### 환영 인사

원본: "환영합니다! 이제 시작해볼까요?"

개선:
```
반가워요.
첫 프로젝트를 만들어볼까요?
```

또는 더 간결하게:
```
안녕하세요.
무엇부터 해볼까요?
```

**핵심:** 느낌표 하나도 아끼고, 환영의 강도를 낮춘다. 토스는 차분함으로 신뢰를 만든다.

### 기능 소개 (툴팁, 코치마크)

원본: "이 버튼을 클릭하면 프로젝트를 생성할 수 있습니다."

개선:
```
여기를 누르면 새 프로젝트를 만들 수 있어요.
```

핵심: 설명은 1줄로, 행동 동사로 시작. "~할 수 있습니다"는 너무 학문적.

### 권한 요청 (알림, 위치, 카메라)

원본: "알림 권한이 필요합니다. 허용해주세요."

개선:
```
알림으로 중요한 소식을 받아볼 수 있어요.
지금 허용할까요?
```

**핵심:** 권한 요청은 **가치를 먼저**, **요청은 나중에**. "왜 필요한지"가 명확하면 허용률이 2배 이상 차이 난다.

원본: "위치 정보가 필요합니다."

개선:
```
근처 매장을 찾아드릴게요.
위치를 알려주시겠어요?
```

### 가입 유도 (지연된 로그인)

원본: "회원가입이 필요합니다."

개선:
```
저장하려면 먼저 계정이 필요해요.
30초면 만들 수 있어요.
```

**핵심:** 가치(저장)를 먼저, 장벽(가입)을 구체적 시간(30초)으로 완화.

## 튜토리얼 패턴

### 단계 안내

원본: "1단계: 프로젝트를 생성하세요."

개선:
```
1. 먼저 프로젝트를 만들어요
```

핵심: "단계"라는 딱딱한 단어 제거, 해요체로 자연스럽게.

### 축하 메시지 (단계 완료)

원본: "축하합니다! 1단계를 완료하셨습니다."

개선:
```
첫 단계 끝났어요.
다음으로 가볼까요?
```

**핵심:** 과한 축하는 사용자를 어색하게 만든다. "끝났어요" 정도로 자연스럽게.

### 전체 완료

원본: "모든 단계를 완료하였습니다. 이제 서비스를 이용해보세요!"

개선:
```
준비가 다 됐어요.
이제 직접 써볼까요?
```

## 사용자 재진입 시 패턴

앱을 오랜만에 다시 연 사용자에게:

원본: "오랜만입니다. 서비스 이용에 감사드립니다."

개선:
```
다시 와주셨네요.
새로 업데이트된 기능을 둘러볼까요?
```

**핵심:** 감사 표현보다 "새로운 가치"를 제시하는 게 재참여율이 높다.

## Before/After 종합 예시

```
케이스 1 — 첫 진입 빈 화면
원본: 생성된 프로젝트가 없습니다. 새 프로젝트를 생성해주세요.
개선: 아직 프로젝트가 없어요. [첫 프로젝트 만들기]
이유: 친근한 상태 설명 + 즉시 행동 가능한 버튼.

케이스 2 — 환영 인사
원본: 안녕하세요! 서비스 가입을 진심으로 환영합니다!
개선: 반가워요. 어떤 걸 먼저 해볼까요?
이유: 과한 환영 톤 제거, 사용자에게 선택권을 준다.

케이스 3 — 알림 권한
원본: 알림 권한을 허용해주세요. 허용하지 않으면 중요한 정보를 놓칠 수 있습니다.
개선: 알림으로 새 소식을 바로 받아볼 수 있어요. 지금 허용할까요?
이유: 부정적 프레임("놓칠 수 있습니다") 제거, 가치 중심으로 전환.

케이스 4 — 검색 결과 없음
원본: 검색 결과가 없습니다.
개선: "{검색어}"에 맞는 결과가 없어요. 다른 검색어로 찾아볼까요?
이유: 구체성(검색어 언급) + 다음 행동 제시.

케이스 5 — 단계 완료
원본: 완료되었습니다!
개선: 다 됐어요.
이유: 수동형·느낌표 제거, 담백함이 토스 톤.
```
