# 토스 라이팅 8원칙

> 출처: https://toss.tech/article/8-writing-principles-of-toss
> 코어 밸류: 명확한 · 간결한 · 친근한 · 존중하는 · 공감하는

## 1. 해요체를 쓴다

상황·맥락·대상을 불문하고 제품 안의 모든 문구는 **해요체**. 일관성이 토스 톤의 기본이다.

- 합니다 → 해요
- 하세요 → 해요
- 하십시오 → 해요
- 되었습니다 → 됐어요
- 불가합니다 → 할 수 없어요 (그리고 가능하면 긍정형으로 다시 변환)

**예외:** 법적 고지, 약관 본문 등은 해요체가 오히려 어색할 수 있어 격식체를 유지. 단, 약관 요약이나 동의 버튼 주변 설명은 해요체.

## 2. 능동형으로 쓴다

수동형은 책임 소재가 불명확하고 거리감이 생긴다. 능동형이 주체를 명확히 한다.

- 등록되었습니다 → 등록했어요
- 처리되지 않았습니다 → 처리하지 못했어요
- 발송될 예정입니다 → 보내드릴게요

**예외:** 주체를 일부러 숨겨야 할 때(예: 개인정보 처리, 자동 시스템 동작)는 수동형 허용.

## 3. 긍정형으로 쓴다

부정 단어("없다", "안 된다", "실패")는 사용자에게 심리적 거리감과 불안을 준다.

- 주문할 수 없어요 → 지금은 주문을 받을 수 없어요. 잠시 후 다시 시도해볼게요.
- 카드 정보가 없습니다 → 카드를 등록하면 바로 결제할 수 있어요.
- 한도 초과입니다 → 한도 내에서 다시 시도해볼게요.

**핵심 패턴:** 부정 → "~하면 할 수 있어요" 구조로 변환.

## 4. 잡초를 뽑는다

넣든 빼든 의미가 그대로인 단어는 잡초. 모바일 화면은 좁다.

- 해당 항목을 선택해주세요 → 항목을 선택해주세요 → 선택해주세요
- 꼭 필요한 경우에만 사용해주세요 → 필요할 때만 사용해요
- 다음 단계로 이동하시려면 → 다음으로 가려면

잡초 후보 단어들: "해당", "본", "꼭", "반드시", "부디", "즉", "그러므로", "따라서", "결과적으로"

## 5. 주어와 시점을 사용자에 맞춘다

시스템 관점("서비스가 준비 중입니다")이 아니라 사용자 관점("금방 준비해서 보여드릴게요").

- 본 서비스는 점검 중입니다 → 지금은 서비스를 이용할 수 없어요
- 시스템 오류가 발생했습니다 → 문제가 생겼어요. 잠시 후 다시 시도해볼게요

## 6. 어려운 용어를 쉽게 푼다

금융·IT 용어를 사용자 언어로 번역한다.

- 인증 실패 → 인증하지 못했어요
- 트랜잭션 오류 → 거래 중 문제가 생겼어요
- 유효하지 않은 요청 → 요청을 처리할 수 없어요

## 7. 일관된 용어를 쓴다

같은 대상을 가리킬 때 용어를 섞지 않는다.

- "상품", "아이템", "제품"을 한 화면에서 혼용 금지
- "회원", "사용자", "유저" 섞어 쓰지 않기
- 한 번 정한 용어를 제품 전체에서 유지

## 8. 상황에 맞는 구두점을 쓴다

- **마침표**: 문장이 끝났음을 분명히 해야 할 때. 짧은 버튼·라벨엔 없어도 됨.
- **느낌표**: 아껴서. 축하·긍정 순간 1회 정도. "완료되었습니다!!!" 같은 건 금지.
- **물음표**: 재확인 상황("정말 삭제할까요?")에서만.
- **이모지**: 거의 쓰지 않음. 써도 한 화면에 1개 이하.

## 빠른 자가 진단 5문항

문구를 쓸 때마다 이 5개만 체크하면 90%는 해결된다.

1. 해요체인가?
2. 능동형인가?
3. 긍정형인가? (부정 단어가 있다면 해결 경로로 뒤집을 수 있는가?)
4. 잡초가 없는가?
5. 사용자 시점인가?
